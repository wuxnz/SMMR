# SMMR operating loop

Use the sequence `DISCOVER → UNDERSTAND → RESEARCH → RETRIEVE → PLAN →
TEST_FIRST → IMPLEMENT → EXECUTE → DIAGNOSE → REPAIR → VERIFY → REVIEW →
MEMORIZE`. Work on one bounded state at a time.

Before network access, research, or durable memory writes, check the active
SMMR permissions. Stop with a blocked result when a budget, permission, or
verification requirement cannot be satisfied. Every completion claim needs
evidence: command, observation, and scope.

Keep the model focused on the current state. Do not skip discovery or tests
because a change appears small.
